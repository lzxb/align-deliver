# MR 持续维护与远程恢复

用于 J0–Z 的提交、等待与恢复阶段。结果应是本任务全部 MR 均经远端确认已合并、关闭或取消；不能把本轮执行结束当成整个目标结束。

## 用同一个任务台账续跑

保存到 SKILL 指定的状态文件；后续批次与调度提示必须能定位同一个入口。

| 记录 | 必要内容 |
|---|---|
| 任务 | 稳定任务标识、目标、已确认原则、全部批次、仓库/工作区与目标上游 |
| 分支与 MR | 所有计划及已创建源分支、逐分支的待建/已建 MR 映射、MR 的仓库/编号/URL、承接批次与旧 MR、依赖、远端状态与核实时间 |
| 验证 | 当前源提交、目标提交、检查范围、验收轮次与证据、对应 CI 提交与状态 |
| 待恢复操作 | 批次、失败步骤、写入意图与预期结果、最近确认结果或未知、错误与下一动作 |
| 调度 | 唯一任务标识、时区/时段、调度句柄、期望与实际状态、下一次触发时间 |
| 执行权 | 当前执行者、执行令牌/租约与到期时间；只记录互斥元数据，不存认证令牌 |

操作前先写意图，操作后写已确认结果；上下文压缩或重启先重读。尚未拿到 MR 编号时，也按仓库与源/目标分支保留创建意图，不把响应丢失当成“尚未创建”。台账不只含当前 MR，也不只含开放 MR。

## 先工作，再安排等待

有可独立推进的研发、验收、提交或恢复工作时先做；已有 MR 不是立即创建定时任务的理由。只有已提交至少一个 MR、当前无可推进工作、全部任务尚未终态，才用宿主实际支持的调度工具创建或复用一个任务级检查。尚无 MR 的网络等待留在当前执行中，有限退避后再查，不新建定时任务；若宿主无法继续运行，保存恢复入口并如实报告能力限制，不宣称会自动醒来。

时区跟随用户设置并写入台账；默认周一至周五，09:00、09:30、……、20:30、21:00 共 25 个时刻，不含 21:30。创建前查询已有任务，优先更新匹配稳定任务标识的那一个。用工具确认创建结果及下一次执行；不能只在提示里写“每天检查”而不落实调度。调度不能精确表示边界时，使用受支持的触发加入口时段判断，时段外不做远程维护；不得声称不支持的精度。

调度提示写清：状态文件入口、仓库、全部 MR 的范围、时区与时段、V→AA→AB→AC、J0 选分支与终态后新 MR 的动作、K 的恢复规则、结束判定；不复制一份会漂移的 MR 清单代替台账。无变化和可自行恢复的短暂故障保持安静，只在有实质进展、持续失败需用户操作或全部终态时通知。

若已有定时任务又出现可做工作，沿用同一任务。当前执行与定时触发使用宿主支持的原子互斥（如本机原子锁，而不是先读后写的布尔标记）；未获得执行权的触发保留任务并结束本轮，不并发改同一分支。每次远程写入与取消调度前校验执行令牌仍有效，租约过期的旧执行者不得继续写入；接管须确认前任已停止或安全交接。运行超过 30 分钟时续租。中断保存检查点，下次从台账恢复，不重新从“新建任务”开始。

## 每轮都先读真实状态

1. 获取执行权，读取全部批次、分支、MR 与未知写入；按记录的原目标和原则恢复。
2. 查询已登记 MR 的具体状态，并按当前源分支执行 J0，而非总取“最近一个 MR”。无关联必须核对历史、待建映射与未知创建意图，精确匹配仓库、源/目标分支及任务归属；只查开放列表为空或收到 404 不足以判定首次交付，多重/不明关联走 K，不接管他人 MR。
3. 已合并、关闭或取消的 MR 记终态并停止旧分支的新 commit、push 和 MR 更新；先按下节核对改动归宿，有新增有效工作转新分支/新 MR，无差异则回 O。关闭/取消不能冒充合并，也不自动重新打开或重做已终止范围；需要裁决走 Q–R，不删未决工作来取消调度。
4. 开放 MR 核对源分支远端提交、最新目标上游、CI 与可合并状态。有冲突或本 MR 导致的 CI 失败，回 G 修复、H–T 验收至 0 修改，再经 J0 更新原 MR、L–M 复核。外部 CI 故障留证等待，不顺手改无关上游。
5. 紧接每次代码 commit、push、MR 写入前查关联状态、源提交和执行权；任何变化先回 J0，吸收他人更新后重新验证，不沿用旧验收。每次写后核对实际结果，commit 后 push 前再次检查；推送期间也可能合并。MR 若已终态，按平台合并/压缩记录及目标实际内容核对覆盖，遗漏转新分支/新 MR。默认不用强制覆盖；需要改写历史时遵循仓库许可并使用明确期望提交的保护，不能盲目 force。所有验证针对最终代码，CI 必须对应当前源提交；上游再次变化时重新判断冲突与受影响检查。
6. 新 MR 一经确认创建，立即登记到同一任务全部 MR 台账，即使 CI 排队或后续查询失败也不能遗漏；原任务级调度继续覆盖它，不另建任务。处理完仍有工作就继续；没有可做工作则核对 AB。旧 MR 终态而新分支待提交、待建 MR 或写入未知时仍不满足 AB，确认无遗漏且全部终态才执行 Z。

## 终态后迁移到新分支、新 MR

1. 先保存原 worktree 的未提交文件、所有待交付提交/补丁及写入检查点；核对平台合并记录与最新目标内容，识别已覆盖部分。尤其压缩合并后旧提交可能不在目标祖先链上，不能仅用提交 SHA/祖先关系判断未合并，更不能整段盲目 cherry-pick 已合并历史。按实际目标内容提取剩余有效差异，必要时使用平台记录、逐项 diff 与原验收证明；无法确定则保持未知并走 K 或 Q–R，不丢原工作。
2. 只有已授权且未被终止的待做工作或差异才继续；尚未编码的已授权工作也应先选新分支再研发，不要求先在旧分支制造差异。既无待做工作也无差异则回 O，不建空 MR；关闭/取消的旧范围不自动重做。写入迁移意图（预期新分支/工作区、差异快照与检查点），同步最新上游成功后，创建新命名的独立分支/工作区，迁移剩余差异；恢复走 RT→JE，先核对实际分支、迁移与登记结果，复用已完成步骤，不因 fetch 或中断重复建分支。失败保留原快照和待恢复意图，不清理尚未确认迁移成功的工作。
3. 立即登记新分支的独立映射为“待创建 MR”，记录目标、批次、旧 MR 与迁移结果；旧分支与旧 MR 终态保留。新分支没有 MR 是正常待交付状态，J0 只查此新映射及精确创建历史，不沿用旧 MR 终态再建一条分支。迁移后回 G–H–I–T；即使差异原先验收过，也须在新上游上重新验证。
4. 若研发后最终无有效差异且无关联 MR，核实目标已满足并登记无需提交，核销该待建意图但保留历史，回 O；不能让空待建映射永久阻止 AB，也不能伪造空 MR。仍有待做/未知工作不得核销。J0 / JC 对新分支核对后按检查点提交/推送，按精确创建意图去重建 MR；响应丢失先查实际结果。新 MR 一经确认就回填编号/URL，描述只解释本次剩余差异，必要时说明承接的旧 MR；已经合并的旧 MR 不再列为未合并依赖。继续 L–M 并维护整个任务。

例如：!1 已合并后又产生改动 B。若 B 尚未 commit，先保全；若已在旧分支 commit/push，先核对其是否被目标覆盖。目标缺 B 时，从最新上游建新分支，仅迁移 B，登记待建 MR，重新验收并创建 !2；目标已有 B 则不造空 MR。!1 的终态不影响 !2 的维护，!2 开放或仍有未提交工作时不能取消唯一调度。

每次远端读取都可能失败。状态未知、合并性计算中、CI 缺失/排队/运行中走 O 先做独立工作，无工作且已有 MR 则进入 C0 等待复查，不滞留在 L/M 饿死后续批次，也不推断通过；查询失败尤其不能解释为 MR 消失或已关闭。取消仅指 MR 自身的终态；流水线/作业取消不代表 MR 已取消。平台没有独立 MR 取消状态时，依实际关闭结果记录，不用 CI 状态代替 MR 状态。

## 任意远程步骤失败都能恢复

同一操作每轮最多 3 次并递增退避，每次设置超时并禁用交互。当前轮仍失败，保存“待恢复”，推进独立工作，不在同轮通过 O/V 重新进入刚耗尽预算的操作形成热循环。只有确认已有有效触发，才可保存后让出本轮并依靠下一次调度；已有 MR 且无工作时可创建/复用正常等待任务。调度创建/取消失败、回执丢失或触发有效性未知时，当前执行须继续有限退避等待并核实；无法维持执行则明确报告待恢复及需要的唤醒能力，不能声称已有自动续跑。权限/认证需用户修复时说明具体所需动作，不能无限尝试登录、扩大权限或要求无关确认；其他 MR 照常维护。

| 失败位置 | 恢复动作 |
|---|---|
| fetch / pull / 查询上游 | 保留本地改动与已确认提交；恢复后重新获取，不用缓存冒充最新，也不把传输错误当代码冲突 |
| push 超时或响应丢失 | 先 J0 核对当前分支关联 MR 与远端是否已到预期提交；已生效不重复推送；未生效且 MR 仍开放（或已核实无关联）、远端未变才重推。终态则核对目标覆盖并迁移遗漏到新分支，不重推旧分支；远端变化先同步并重新验收 |
| 创建 / 更新 MR 响应丢失 | 回 J0 查精确创建意图、当前分支关联 MR 与实际描述，发现匹配结果立即登记；终态按覆盖情况处理，不能重复创建或继续写旧 MR |
| MR / CI 查询失败 | 保留最近已确认状态并标未知；重查后再决定，不能记绿、无冲突或终态 |
| 创建 / 更新调度响应丢失 | 按稳定任务标识查询已有任务，复用实际句柄；若工具不可用保持当前恢复入口，不伪造已安排的执行 |
| 取消调度失败或响应丢失 | 保存“期望取消、待核实”，查询实际状态，已取消才记完成；仍有效则续接取消步骤 |

提交相关恢复统一经 RT→J0，先确认服务器实际结果与当前分支映射，重复执行只在必要时发生。新一轮先重置有限重试预算，再处理台账，不因上一轮失败丢弃整个任务。

## 结束的是整个任务的维护

取消前必须取得覆盖**全部本任务 MR**的有效核实结果，证据不足或无法证明台账完整时保持未知：MR 集合非空，均已合并、关闭或取消，无尚未提交的批次、未知写入、待恢复/待交付/待定工作。核实期间发现新 MR 或台账变化，重新盘点；单个 MR 终态只更新一行。取消与新工作登记共享执行权，防止刚登记 MR 就误取消任务。

业务终态核实后先写入“收尾/期望取消”，这条控制操作未知不单独算作业务未完成。取消或核实失败走 ZF，当前执行等待工具恢复，不依赖其下一次触发；恢复先回 V 重读台账并刷新全部 MR，确认业务结束条件仍成立，再核实实际调度，已取消则完成核实，仍有效才继续取消。真正取消前后都核对全部 MR 与台账；若等待期间 MR 被重开或出现新工作，撤销收尾回 O/V，已取消的调度在再次满足 C0 时恢复为唯一任务，不继续盲目取消。取消后查询工具实际状态并保存证据，汇报各终态与未实现的目标；关闭/取消不等于目标成功。调度停止后若用户新增工作或重开 MR，按新授权恢复工作，在再次无工作时重新核实并安排维护，不擅自处理用户已终止的 MR。
